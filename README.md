# Kamron APP — мобильный HTML MVP

Личный центр дня в формате iPhone. Откройте `index.html` для просмотра без интернета — приложение не зависит от внешних библиотек. На HTTPS или локальном сервере (`npm run serve`) service worker кэширует файлы, и приложение ставится на домашний экран как обычное.

Помощник Jarvis работает в двух режимах: локально — подготовка, контекст и выгрузки без вызова модели; с подключённым сервером (`server/`) — живой диалог и разбор ответов по семинару. Ключи моделей живут только на сервере.

## Что работает

- **Главный экран без прокрутки:** четыре направления, прогресс режима дня, следующий пункт расписания, ближайшая задача, заметка, баллы и серия дней.
- **Навигация:** внизу только «Главная», «День» и «Ещё». На экране «Ещё» собраны заметки, задачи, прогресс, работа, универ, зал, игры и настройки. Поиск и Jarvis доступны сверху из любого раздела. При возврате из проекта, предмета или страницы Jarvis список остаётся на прежнем месте.
- **Jarvis:** кнопка ✦ в верхней панели открывает единый экран помощника. Оттуда доступны живой диалог, голосовой сценарий, подготовка к занятиям, контекст существующих проектов и технические запросы. Переход к проекту или предмету работает и при нескольких записях; при пустом списке можно сразу создать первую. **Живой диалог и разбор ответов по семинару работают с подключённым сервером** (папка `server/`): модель отвечает, зная ваш режим дня, задачи, занятия, проекты и заметки. Без сервера остаются локальные сценарии, и приложение прямо говорит об этом.
- **Поиск и быстрые действия во всём приложении:** значок лупы в верхней панели открывает поиск по проектам, личным и рабочим задачам, заметкам, предметам, заданиям и событиям. Там же можно создать личную задачу, запись, событие, рабочую задачу, задание, проект или предмет. На компьютере поиск открывается сочетанием ⌘ K / Ctrl K.
- **Удобное редактирование:** формы предупреждают перед закрытием с несохранёнными изменениями. Ответы для самопроверки на семинаре сохраняются во время ввода и при уходе со страницы.
- **Все задачи:** общий список личных дел, работы и универа с фильтрами «Активные», «Сегодня», «Впереди», «Важные», «Без срока» и «Готово». Одна кнопка добавления предлагает тип задачи: личная, работа или универ. Личное дело создаётся без проекта или предмета. Задачи можно искать, выполнять, редактировать и открывать в исходном разделе; после быстрого добавления новая задача сразу видна в списке. Просроченную или сегодняшнюю задачу можно одним нажатием перенести на завтра и отменить это действие.
- **Моя неделя:** график выполненных задач по дням, результаты личных дел, работы, университета и тренировок, недельная цель, прогресс режима дня за семь дней и ближайшие просроченные задачи. Из карточки тренировок можно открыть журнал зала. Экран открывается по карточке баллов на главной, через быстрые действия и настройки.
- **Режим дня:** готовый редактируемый шаблон будних и выходных дней, пункты на одну дату или с повтором по выбранным дням, календарь и обзор недели. Большая строка с датой и стрелками убрана: выбранный день показан компактно, соседние дни открываются в недельной ленте, другие даты — через кнопку календаря. Выбранную дату можно быстро вернуть к сегодняшней. Карточка «Дальше по плану» ведёт к нужному пункту; ближайший пункт можно отметить выполненным прямо с неё. У каждого пункта крупная кнопка выполнения и отдельный понятный статус: впереди, можно отметить, готово или без отметки. За отметку начисляется 10 баллов; она хранится для конкретной даты, поэтому повторяющийся пункт остаётся в следующих днях. Повторное нажатие снимает отметку и баллы. Будущие дни отметить нельзя. Прогресс показывает, сколько пунктов осталось; завершённые даты выделены в календаре. При изменении расписания отметки на датах, где пункта больше нет, удаляются вместе с лишними баллами. Пары из университета автоматически попадают в расписание, и прямо там можно отметить посещаемость. На выбранный день можно добавить личную задачу; задачи со сроком и просроченные видны рядом с планом.
- **Работа:** создание проекта с эмодзи или собственным логотипом, описание как документация, редактируемые рабочие заметки и задачи со сроками. Проекты можно искать по названию и описанию. В списке проектов и внутри каждого проекта показан следующий шаг с быстрым переходом к задаче. Выполнение задачи меняет состояние и прогресс. Поиск ведёт к конкретной рабочей заметке. У каждого существующего проекта есть экран «Jarvis · проект»: он показывает цель, описание, открытые задачи и последнюю заметку, хранит отдельные поручения и выгружает их вместе с контекстом в Markdown для Claude Code. Можно сохранить ссылки на GitHub и Railway; по явному нажатию приложение читает последний коммит репозитория. Без сервера доступны только публичные репозитории; **с подключённым сервером читаются и закрытые** — токен GitHub живёт на сервере, а не в браузере. Статус деплоев Railway сервер отдаёт методом `/api/railway/project`, в интерфейс он пока не выведен.
- **Универ:** сводка пар и дедлайнов, поиск предметов, быстрое добавление задания, преподаватель, аудитория, длительность, материалы и заметки по предмету. Доступны режимы «лекция ↔ семинар», «только лекции», «только семинары» и «без деления». При чередовании тип меняется на каждом фактическом занятии в выбранные дни. Отменённая пара пропускается в последовательности, а посещаемость прошлых занятий отмечается вручную. Задания можно редактировать, ставить срок и приоритет, фильтровать по состоянию. Расписание всех предметов или одного предмета выгружается в файл `.ics` на ближайшие 90 дней с учётом отменённых пар; его можно открыть в приложении «Календарь». На странице предмета можно создать несколько подготовок к занятиям: указать тему и контекст, приложить фото, документ или презентацию, ответить на вопросы самопроверки и скачать Markdown-пакет для ChatGPT. Текстовые файлы `.txt` и `.md` до 300 КБ добавляются в пакет текстом; другие исходные файлы нужно приложить к ChatGPT отдельно. **С подключённым сервером** появляется кнопка «Разобрать мои ответы»: Jarvis читает ответы вместе с приложенными картинками и PDF, указывает пробелы и даёт три пункта на повторение.
- **Зал:** календарь и журнал завершённых тренировок с типом, длительностью и заметкой об упражнениях или самочувствии. Дни с записями отмечены в календаре; записи можно менять и удалять. С выбранной даты можно вернуться к сегодняшней одним нажатием. Будущий персональный план добавим после вашего описания целей и графика.
- **Заметки:** отдельные категории, поиск по заголовку и тексту, закрепление одним нажатием и быстрый просмотр на главном экране. Отредактированные записи поднимаются выше среди незакреплённых. Новую заметку можно создать прямо с главного экрана.
- **Мотивация:** 50 баллов за выполненную личную, рабочую или учебную задачу и 10 баллов за пункт режима дня на конкретную дату. Новый уровень каждые 250 баллов. Серия учитывает дни с выполненной задачей или пунктом режима. Снятие отметки возвращает соответствующие баллы; случайное выполнение задачи можно отменить в течение шести секунд. На экране прогресса баллы задач и режима показаны отдельно.
- **Игры:** «Блоки» с полем 8×8, тремя фигурами, очисткой линий, комбинациями и окончанием при отсутствии возможного хода; 2048 с двумя стартовыми плитками, стандартными правилами объединения, победой на 2048 и продолжением партии; поиск пар с ходами и рекордом. Доступны нажатие или перетаскивание блоков, свайпы и кнопки для 2048. Правила каждой игры раскрываются по кнопке «Как играть». У каждой игры своя узнаваемая палитра. Игры работают без сети, партии и рекорды сохраняются; после прерывания хода в «Парах» можно продолжить игру. Повреждённые сохранения отдельных игр сбрасываются без затрагивания остальных данных. Перед сбросом незавершённой партии приложение спрашивает подтверждение. «Блоки» воспроизводят открыто описанные правила Block Blast; точная внутренняя выдача фигур и подсчёт очков оригинала не опубликованы, поэтому в макете используются собственные варианты этих правил.
- **Настройки:** доступны через «Ещё». Основной экран содержит имя, четыре темы по настроению («Небо», «Ночь», «Шалфей», «Рассвет»), напоминания, Jarvis и прогресс. В «Дополнительно» находятся голосовой сценарий, снижение анимаций, недельная цель, технические запросы, подключение сервера Jarvis с проверкой связи, экспорт и импорт JSON, сброс данных. Голосовой сценарий также доступен из Jarvis. Старые темы при загрузке данных переводятся в новые автоматически.
- **Голос Jarvis:** отдельный экран с утренним и вечерним временем, выбором дней и тона, профилем Telegram, предварительным планом на сегодня и завтра, а также личным вечерним отчётом. Эти данные сохраняются локально и входят в JSON-копию. Реальные звонки пока не активны; проверенный путь подключения описан в `VOICE_ASSISTANT.md`.
- **Jarvis · приложение:** доступен из настроек и быстрых действий. Проверяет локальное сохранение, отметки режима дня, объём данных, ширину текущего экрана и состояние офлайн-режима. Повреждённые ссылки на удалённые пункты расписания можно исправить одним нажатием. Запросы на исправление, изменение дизайна и новые функции сохраняются в приложении; каждый запрос выгружается как готовое Markdown-задание для Claude Code. Запросы входят в резервную копию данных.

В каждом разделе есть краткая сводка и заметное основное действие. В расписании видны отметки выполнения и задачи выбранного дня; в проектах и предметах — прогресс и задачи; в университете — следующие пары и дедлайны; в заметках — быстрый ввод и закреплённые записи. «Зал» остаётся подготовленным местом для персонального плана, который составим после вашего описания.

Карточка задач на главном экране открывает общий список. Результаты глобального поиска по задачам ведут к конкретной задаче в её проекте или предмете и подсвечивают её.

Интерфейс использует HTML/CSS-версию стеклянной навигации: полупрозрачная нижняя панель, размытие фона, световые грани и мягкие анимации. Карточки с эмодзи-стикерами сохраняют ясность текста. Типографика опирается на системный шрифт iPhone и работает без загрузки шрифтов из сети. Короткие анимации появления и нажатия используют смещение и прозрачность; постоянных движущихся эффектов нет. Настройка «Меньше анимаций» и системное сокращение движения отключают эти эффекты. Это визуальный прототип; нативный материал Liquid Glass появится только при последующей реализации в iOS.

## Данные и уведомления

Данные хранятся в `localStorage` текущего браузера на этом устройстве. Для переноса между браузерами есть экспорт и импорт JSON, включая личные задачи, отметки режима дня, темы подготовки, ответы, ссылки и поручения по проектам. Старые сохранения открываются с новыми разделами пустыми; некорректные поля в импортированной копии приводятся к безопасному виду, а повреждённые записи пропускаются. Логотип проекта ограничен 400 КБ, чтобы не переполнить локальное хранилище.

Прикреплённые файлы семинаров хранятся отдельно в IndexedDB этого браузера; каждый файл ограничен 15 МБ, всего до 10 файлов на тему. **Сами файлы не входят в JSON-копию и не переносятся с ней на другое устройство.** Сохраняйте исходные документы отдельно. При импорте копии список вложений может отображаться без доступного файла: приложение сообщит об этом при открытии. При удалении подготовки, её предмета или сбросе данных связанные локальные файлы удаляются.

HTML-версия проверяет напоминания, пока страница открыта. Событие напоминается за выбранное число минут; задачи со сроком — утром в день срока. При поддержке браузера может появляться системное уведомление. **Гарантированные фоновые уведомления на iPhone** требуют нативной реализации через Xcode.

**Виджет на домашнем экране iPhone** показан как раскрываемый образец в дополнительных настройках. Рабочий виджет появится на этапе нативной сборки: понадобится WidgetKit и общий контейнер данных между приложением и виджетом.

## Сценарии Jarvis

**Локально, без сервера.** Подготовка к семинару, сохранение материалов и ответов, контекст существующих проектов, чтение последнего публичного коммита GitHub, Markdown-поручения для Claude Code, проверки приложения и исправление повреждённых отметок режима дня. Модель при этом не вызывается, и приложение прямо говорит, что работает в локальном режиме.

**С сервером** (папка `server/`, разворачивается на Railway) добавляются:

- живой диалог: модель отвечает по снимку дня — режим, открытые задачи, ближайшие занятия, проекты и последние заметки;
- разбор ответов по семинару вместе с приложенными картинками и PDF;
- последний коммит закрытого репозитория GitHub;
- статус деплоев Railway (метод сервера готов, в интерфейс не выведен).

Ключи Anthropic, OpenAI, GitHub и Railway задаются **только переменными окружения на сервере** и в приложение не вводятся. В приложении хранится адрес сервера и личный ключ доступа к нему: он защищает ваш же сервис от чужих запросов. Адрес принимается только по `https`, исключение — `localhost` при локальной разработке.

Переписка и разборы живут в памяти открытого экрана: на сервере они не сохраняются, в `localStorage` не попадают и в резервную копию не входят.

Чего по-прежнему нет: приложение не правит собственный исходный код. Технический агент должен создавать отдельную ветку или pull request, запускать проверки и возвращать изменения на просмотр; публикация — после подтверждения.

Для **настоящего входящего Telegram-звонка** обычный бот не подойдёт: метод начала частного вызова доступен пользовательскому аккаунту. Решение для следующего этапа — отдельный аккаунт помощника, серверный клиент Telegram с поддержкой частных звонков, аудиомост к OpenAI GPT-Live и защищённая синхронизация планов. Подробный поток и проверки находятся в `VOICE_ASSISTANT.md`.

Нативное iPhone-приложение также не сможет произвольно менять уже установленный исполняемый код: исправления интерфейса и логики будут приходить через обновление приложения или через развёртываемую веб-часть.

## Как устроен проект

```
index.html          оболочка: верхняя панель, страница, навигация, модальное окно
styles.css          интерфейс и четыре темы
app.js              СБОРКА из src/ — редактировать напрямую нельзя
src/                исходный код
  core/             состояние, выборки данных, утилиты, константы, иконки
  ui/               каркас страницы и повторяющиеся блоки разметки
  views/            экраны: главная, режим дня, работа, универ, зал, заметки, задачи, диалог
  forms/            модальное окно и разметка всех форм
  games/            «Блоки», 2048, «Пары»
  features/         задачи, файлы семинаров, экспорт, напоминания, связь с сервером
  main.js           точка входа: обработчик действий, жесты, запуск
server/             сервер Jarvis для Railway
telegram-call/      спайк звонков в Telegram (отдельный сервис на Python)
tools/              сборка, иконки, проверка, локальный сервер
tests/              сквозные проверки в браузере
icons/              иконки приложения, PNG генерируются из SVG
```

### Команды

| Команда              | Что делает                                                   |
| -------------------- | ------------------------------------------------------------ |
| `npm install`        | ставит инструменты разработки                                |
| `npm run build`      | собирает `src/` в `app.js` и обновляет версию кэша в `sw.js` |
| `npm run watch`      | то же, но пересобирает при каждом изменении                  |
| `npm run serve`      | локальный сервер на `http://localhost:4173`                  |
| `npm run check`      | ищет в `app.js` потерянные импорты (разбор парсером)         |
| `npm test`           | 18 сквозных проверок в браузере                              |
| `npm run test:setup` | один раз ставит браузер для тестов                           |
| `npm run icons`      | пересобирает PNG-иконки из `icons/*.svg`                     |
| `npm run format`     | приводит форматирование к общему виду                        |

**Почему `app.js` — сборка, а не исходник.** Страница должна открываться и просто из файла, а ES-модули в этом режиме запрещены политикой источников браузера. Один классический скрипт открывается и локально, и с хостинга, и кэшируется service worker одной записью. Поэтому правки вносятся в `src/`, а `app.js` пересобирается командой `npm run build` и попадает в репозиторий вместе с ними.

### Публикация

Приложение публикуется на GitHub Pages из ветки `main`: workflow `.github/workflows/pages.yml` заново собирает `app.js` из `src/`, проверяет импорты и выкладывает только файлы приложения — без `src/`, `server/`, `tests/` и инструментов. Второй workflow прогоняет сборку и сквозные тесты на каждый push и pull request.

Сервер разворачивается отдельно на Railway из папки `server/` — на Pages серверная часть работать не может, это статика.

### Сервер Jarvis

Разворачивается на Railway из папки `server/`. Переменные окружения описаны в `server/.env.example`: ключ доступа `APP_ACCESS_TOKEN`, список разрешённых источников, ключ провайдера модели и при необходимости токены GitHub и Railway. После развёртывания адрес и ключ вводятся в приложении: Настройки → Дополнительно → Сервер Jarvis → «Проверить связь».

**Расход на модель.** Сервер считает стоимость каждого ответа по фактическим токенам и цене из `PRICE_INPUT_PER_M` / `PRICE_OUTPUT_PER_M`, а при достижении `DAILY_USD_LIMIT` отклоняет запросы до следующих суток. Текущий расход виден в `/api/health`. Счётчик живёт в памяти процесса и обнуляется при передеплое — это защита от случайного цикла, а не бухгалтерия: жёсткий предел задавайте в личном кабинете провайдера.

## Передача в Claude Code / Xcode

Поведение приложения описано модулями в `src/`, оформление — в `styles.css`. При переносе лучше сохранить структуру данных и правила предметов, но заменить `localStorage` на нативное хранение, напоминания — на локальные уведомления iOS, а виджет — на WidgetKit. Сервер `server/` переносить не нужно: нативное приложение обращается к нему так же, как веб-версия. Для раздела «Зал» сначала нужно получить ваш реальный график, цель и упражнения.
