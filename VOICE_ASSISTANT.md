# Jarvis в Kamron APP: Telegram-звонки

## Проверенное решение

Обычный Telegram-бот не может начать личный голосовой вызов. Метод Telegram `phone.requestCall` доступен только пользовательским аккаунтам. Поэтому звонящий помощник должен иметь **отдельный Telegram-аккаунт**, отличный от аккаунта Камрона. Бот можно добавить позже для текстовых сообщений, но он не заменяет звонящий аккаунт.

Для серверного клиента использовать Telegram MTProto (например, Telethon) вместе с PyTgCalls / NTgCalls. NTgCalls заявляет поддержку частных звонков и потокового аудио. Это сторонняя библиотека; прежде чем обещать функцию как будильник, нужно проверить её на выбранном сервере и на реальном iPhone. Альтернатива для высокой надёжности — звонок на номер через SIP-провайдера и OpenAI GPT-Live.

Источники: [Telegram `phone.requestCall`](https://core.telegram.org/method/phone.requestCall), [процесс личного вызова](https://core.telegram.org/api/calls), [NTgCalls](https://github.com/pytgcalls/ntgcalls), [OpenAI GPT-Live WebSockets](https://developers.openai.com/api/docs/guides/voice-websockets).

## Поток одного звонка

1. Постоянно работающий сервер берёт локальное время `Asia/Tashkent` и проверяет включённое расписание. Для каждого вида звонка и даты сохраняет ключ попытки **до** начала вызова, чтобы перезапуск или тайм-аут не вызвал второй звонок.
2. Сервер получает актуальный снимок Kamron APP: расписание, ближайшие учебные занятия, открытые и выполненные задачи, предыдущий отчёт. HTML-макет хранит данные в `localStorage`, поэтому перед настоящим запуском нужен защищённый обмен данными с сервером. Закрытая вкладка не может сама передать изменения утром.
3. Выделенный Telegram-аккаунт делает исходящий частный вызов аккаунту Камрона. Сервер ждёт состояния «звонит», «отвечено», «отклонено», «ошибка»; записывает исход. Если не ответил — ограниченная повторная попытка **только по явно заданному правилу**, с проверкой состояния первого вызова.
4. Когда Камрон ответил, сервер запускает OpenAI `gpt-live-1` через WebSocket. Входящий звук Telegram преобразуется в формат, выбранный в Live-сессии (пример OpenAI: mono PCM16, 24 кГц), и отправляется как `session.input_audio.append`. Выходной `session.output_audio.delta` декодируется, преобразуется под NTgCalls и передаётся в Telegram. Требуются очереди, порядок кадров, подавление собственного эха, обработка прерывания речи и закрытие сессии при завершении звонка.
5. Утром ИИ первым приветствует Камрона, кратко читает 2–4 главных события, называет ближайший дедлайн и спрашивает, что нужно изменить. Затем свободно общается. Вечером спрашивает о выполненном и невыполненном, сравнивает с **фактическими отметками** в приложении и формулирует одно конкретное действие на завтра. Строгий тон допускает прямое замечание без оскорблений и унижения.
6. Транскрипт можно сохранять только при включённой пользователем настройке. Итог звонка должен отдельно показывать подтверждённые пользователем изменения. Модель не отмечает задачи выполненными по догадке; изменение задач проходит через серверное действие с проверкой владельца.

## Что требуется для рабочего запуска

- Отдельный номер для нового Telegram-аккаунта помощника и первая авторизация этого аккаунта.
- Telegram API ID / API hash для MTProto; сессионные данные аккаунта хранить только на сервере, с ограниченным доступом.
- OpenAI API key с доступом к GPT-Live; хранить только на сервере.
- Сервер, работающий круглосуточно; закрытая HTML-страница или спящий ноутбук не смогут инициировать звонок.
- Telegram-аккаунт Камрона с разрешёнными звонками от аккаунта помощника; реальные настройки звонков, звука, режима сна и сети на iPhone проверить отдельно.
- Защищённое соединение приложения с сервером и синхронизация планов. Токены Telegram и OpenAI нельзя вводить в HTML-форму, хранить в `localStorage` или включать в резервную копию приложения.

## Проверки перед включением расписания

1. Ручной тест вызова между отдельным аккаунтом помощника и аккаунтом Камрона.
2. Двусторонний разговор: звук, задержка, перебивание ИИ, отключение, занятый абонент, нет ответа.
3. Проверка времени `Asia/Tashkent`, перезапуска сервера и защиты от повторного звонка.
4. Проверка, что ИИ знает только синхронизированные данные и не выдумывает выполненные дела.
5. Проверка на iPhone с заблокированным экраном. Telegram-уведомления и ограничения iOS могут влиять на доставку; HTML не гарантирует пробуждение.

## Состояние текущего MVP

В `index.html`/`app.js` есть экран голосового помощника: время, дни, тон, профиль Telegram, предварительный план и вечерний отчёт. Всё сохраняется локально. **Реальные звонки и OpenAI API пока не подключены**, статус показан явно. Следующий этап — создать и авторизовать отдельный Telegram-аккаунт, затем реализовать и проверить аудиомост на сервере. После успешного сквозного теста можно включать расписание в интерфейсе.
