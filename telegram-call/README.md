# Звонки Telegram — спайк

Цель этого шага одна: выяснить, доходит ли реальный звонок от аккаунта-помощника
до телефона и слышна ли в нём речь. Разговора с моделью здесь **нет** — он дороже
текста примерно в сто раз, и строить его имеет смысл только после того, как сам
звонок подтверждён.

## Почему отдельный аккаунт, а не бот

Бот не может начать личный звонок: метод `phone.requestCall` доступен только
пользовательскому аккаунту. Поэтому нужен второй аккаунт Telegram, который
работает как клиент MTProto. Звук в разговор подаёт `pytgcalls` поверх нативной
библиотеки `ntgcalls` — она поддерживает личные звонки, а не только групповые.

**Риск:** автоматизированный пользовательский аккаунт Telegram может ограничить
или заблокировать. Аккаунт звонит только вам, но гарантий нет — не привязывайте
к нему ничего важного.

## Что нужно подготовить

1. **`api_id` и `api_hash`** — на https://my.telegram.org, раздел API development
   tools, под аккаунтом помощника.
2. **Строку сессии.** На своей машине:
   ```
   pip install telethon
   python telegram-call/session.py
   ```
   Telegram пришлёт код подтверждения — введите его. Скрипт напечатает строку
   сессии. **Это полный доступ к аккаунту, равный паролю:** вставьте её в
   переменную `TG_SESSION` на Railway и больше нигде не храните.
3. **`TG_TARGET`** — ваш `@username` или числовой id: кому звонить.
4. **`OPENAI_API_KEY`** — для озвучки реплики.

Полный список переменных — в `.env.example`.

## Развёртывание

Отдельный сервис на Railway, корень сборки `/telegram-call`, сборщик —
Dockerfile (нужен ffmpeg, поэтому не nixpacks).

## Проверка

```
GET  /health          — что настроено, авторизован ли аккаунт, остаток квоты
POST /call            — {"text": "фраза"}; заголовок Authorization: Bearer <APP_ACCESS_TOKEN>
```

Успешный ответ содержит `дозвонился: true` и длительность. Неуспешный — причину
отказа: не авторизован, исчерпана квота, абонент не ответил.

## Предохранители

Звонок будит человека и стоит денег, поэтому ограничения заданы по умолчанию,
а не «когда-нибудь»:

- `MAX_CALLS_PER_DAY` (6) — больше звонков в сутки сервис не сделает;
- `MAX_CALL_SECONDS` (90) — зависший звонок кладётся принудительно;
- счётчик увеличивается **до** набора, поэтому обрыв связи не даёт позвонить
  второй раз за ту же попытку;
- одновременно идёт не больше одного звонка.

## Если спайк удался

Следующий шаг — заменить одну реплику на разговор: аудиомост к realtime-модели.
Считайте бюджет заранее: голос стоит $0.02–0.11 за минуту против $0.0002 за
сообщение в текстовом диалоге.

## Выключатель платного

`AI_ENABLED` по умолчанию `0` — тот же выключатель, что у бота. Здесь он
важнее вдвойне: живой разговор с моделью самое дорогое, что есть во всём
хозяйстве.

Выключенным он останавливает и живой разговор (`realtime`), и озвучку
(`speech`), и не заводит звонки по расписанию. Проверка стоит у самих
платных примитивов, а не только в обработчиках запросов.

Отдельно стоит знать: дневной лимит `MAX_DAY_COST` прикрывает только
`talk`. Звонок с озвучкой (`call_and_say`) через него не проходит, так
что лимит — не выключатель. Выключатель — `AI_ENABLED`, а немедленно и
наверняка расход останавливает убранный `OPENAI_API_KEY`.

`/здоровье` показывает `ии_включен`.
